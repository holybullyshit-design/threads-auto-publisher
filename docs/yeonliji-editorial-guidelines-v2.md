## 2. 채널의 약속

“관계 고민을 명리의 구조로 풀어 설명하는 사주 웹툰.”

독자는 공감하러 들어와서 사주 개념 하나를 이해하고, 자기 경우에 무엇을 더 살펴야 하는지 알고 나간다.
심리 조언 끝에 사주 단어만 붙이지 않는다. 반대로 용어를 많이 나열하는 것도 전문성이 아니다.

대상은 연애·재회·결혼·부부 문제를 고민하는 20~40대 여성이다.
여성을 항상 기다리고 매달리는 인물로, 남성을 항상 회피하거나 잘못한 인물로 고정하지 않는다.
사주는 전통적인 해석 체계로 소개하며, 과학적으로 확인된 성격 진단이나 미래 예측처럼 말하지 않는다.

## 3. 원고의 필수 통과 기준

7장 기준으로 중앙 3장은 사주 설명과 적용을 담당한다. 이는 편집 목표이며 단어 수를 기계적으로 맞추라는 뜻이 아니다.
핵심 개념은 1개, 보조 개념은 최대 2개다. 새 용어가 나올 때마다 첫 등장 위치에서 쉬운 뜻을 붙인다.

반드시 독자가 다음 세 질문에 답할 수 있어야 한다.

1. 무엇을 보는가? — 글자, 자리, 관계, 시간 중 정확한 대상.
2. 어떤 조건에서 그렇게 읽는가? — 적용 기준과 비교 대상.
3. 같은 단어가 있어도 왜 해석이 달라지는가? — 실제로 달라지는 요소 하나 이상.

탈락 예:
“화개살은 혼자 있는 성향이야. 하지만 사주 전체를 봐야 해. 오늘은 대화해 봐.”

통과 방향:
“화개는 정해진 지지 관계로 살피는 신살이야. 혼자 있고 싶다는 행동만으로 판정하지 않아.
적용하는 기준과 해당 글자의 위치를 먼저 확인하고, 전통적으로 말하는 몰입·고독의 상징을 관계 장면에 연결해 설명해.”
실제 성립표를 넣을 때는 검토된 자료가 있어야 한다.

### ‘전체를 봐야 한다’도 설명한다

“원국이 안정적이면 좋고 흔들리면 나쁘다”는 말은 설명이 아니다.
해당 편에서 무엇을 더 보는지 구체화한다.
예: 같은 충이라도 어느 자리에 생기는지, 다른 글자와 어떤 관계를 맺는지.
설명할 수 없는 요소를 권위를 높이기 위해 나열하지 않는다.

## 4. 사주 근거 카드: 기획 전에 작성

각 주제에 다음 항목을 가진 factPack을 붙인다.

- 핵심 개념과 쉬운 정의
- 적용 기준: 일간/년지/일지 등 어느 기준인가
- 성립 조건: 표·글자 관계·계산 규칙
- 필요한 입력 정보와 아직 알 수 없는 것
- 전통 해석의 범위와 학파 차이
- 관계 이야기로 연결할 수 있는 설명
- 그 개념만으로 말할 수 없는 결론
- 자료 제목·URL 또는 서지·확인일·확인자
- 검토 상태: 미확인 / 보완 필요 / 제작용 확인 완료

출처별 역할을 구분한다.
- 만세력 계산: 사용 라이브러리·절기·시간대 검증 대상.
- 명리 규칙: 출처와 적용 관습을 확인.
- 연애 장면: 이해를 돕는 창작 사례. 실제 고객 사례로 포장하지 않음.
- 해석: 전통적 읽기이며 사실·진단으로 확정하지 않음.

서버의 sajuFacts.js도 검토의 출발점이지 모든 해석의 정답은 아니다.
년지로 정리된 신살표를 일지 기준이라고 바꿔 말하지 않는다.
원국의 巳를 설명하면서 무조건 “뱀띠 사람”이라고 표현하지 않는다.
자료가 없으면 전문 용어를 생성해 채우지 말고 해당 기획을 보류한다.

기초 개념 참고: [한국민족문화대백과사전 ‘사주’](https://encykorea.aks.ac.kr/Article/E0025957).
이 자료는 사주의 구성과 전통 체계를 설명하는 근거이며, 특정 신살의 연애 효과나 재회 예측의 검증 자료는 아니다.

## 5. 7장 이야기 구성

| 장 | 역할 | 반드시 담을 것 |
| --- | --- | --- |
| 1 | 관계 질문 + 사주 관점 | 고민을 짚는 제목, 이번에 살필 명리 대상 |
| 2 | 짧은 상황극 | 대사·행동·맥락. 독자를 진단하지 않음 |
| 3 | 해석의 지도 | 개념의 위치와 뜻, 필요하면 간단한 도식 |
| 4 | 조건과 비교 | 실제로 무엇을 대조하는지, 성립 조건 |
| 5 | 적용과 오해 해소 | A와 B의 차이. 일반 조언으로 이탈하지 않음 |
| 6 | 내 경우의 질문 | 개인 풀이에서 확인할 지점, 이야기 회수 |
| 7 | 의미 있는 참여 | 주제에 맞는 단어·질문, 정직한 다음 행동 |

6장으로 줄이면 2·3장을 결합한다. 사주 설명을 먼저 삭제하지 않는다.
상황극형·비교형·오해 교정형·개념 해설형을 번갈아 사용하되 세 가지 필수 질문은 유지한다.
매 장을 억지로 끊거나 정답을 전부 상담으로 미루지 않는다. 저장할 만한 설명은 게시물 자체에서 완결한다.

## 6. 소재를 늘리는 편집 체계

| 축 | 가능한 질문 | 사용할 수 있는 명리 관점 |
| --- | --- | --- |
| 궁합 | 끌리는 관계와 함께 살기 편한 관계는 같은가 | 두 명식의 글자 관계, 오행 |
| 재회 | 다시 만나는 것과 관계가 달라지는 것은 같은가 | 관계 구조와 시기를 구분 |
| 결혼 | 오래 만났는데 결혼 이야기는 왜 별개일까 | 배우자궁, 두 사람의 명식 |
| 부부운 | 맞춰 사는 것과 참으며 사는 것 | 배우자궁과 상호 관계 |
| 이혼·별거 | 충이 있으면 이혼한다는 말은 맞을까 | 충의 조건과 해석 한계 |
| 새로운 인연 | 도화가 있으면 연애가 쉬울까 | 도화의 기준과 상징 |
| 일주 | 경진일주라는 이름에서 실제로 알 수 있는 것 | 일간·일지, 나머지 기둥의 필요성 |
| 신살 오해 | 화개·귀문을 성격 진단처럼 써도 될까 | 성립 기준, 해석 범위 |

운명·삼재는 불가피한 재앙이나 만남의 보장으로 쓰지 않는다.
경진일주·무술일주를 포함하되 “무조건 이런 여자/남자”라는 고정 성격표로 만들지 않는다.
귀문관살을 정신질환·집착·위험성의 증거로 연결하지 않는다.
이혼 편에서 안전을 위협하는 관계를 운명이라며 견디라고 권하지 않는다.

### 첫 주제 후보 10개

1. 배우자궁에 충이 있으면 정말 이혼할까? — 충과 결혼 결과를 구분.
2. 합이 있으면 무조건 좋은 궁합일까? — 연결의 상징과 관계의 질 구분.
3. 재회운을 볼 때 ‘다시 연락’과 ‘오래 갈 관계’를 나누는 이유.
4. 경진일주, 두 글자로 연애를 어디까지 설명할 수 있을까?
5. 무술일주인데 성격이 다른 두 사람 — 일주 밖에서 더 볼 것.
6. 도화살이 있다고 결혼도 쉬운 건 아닐까? — 매력과 관계 유지의 구분.
7. 화개살이 있으면 혼자 살아야 한다는 말, 왜 조심해야 할까?
8. 귀문관살을 ‘전 애인에게 집착하는 살’이라고 부르면 안 되는 이유.
9. 같은 띠인데 궁합 풀이가 달라지는 이유 — 년주와 전체 명식.
10. 오래 만난 커플도 결혼 전에 궁합에서 따로 확인할 질문.

이는 주제 후보이며 신살의 상세 판별·해석은 factPack 검토 후 원고화한다.

### 중복 관리

제목 외에 중심 질문·사주 원리·장면·비교 구조·독자가 얻는 결론·CTA를 기록한다.
최근 30편 또는 최근 90일 중 더 넓은 기록과 비교한다.

- 같은 중심 질문 + 같은 원리 + 같은 결론이면 제목을 바꿔도 반려.
- 최근 10편에서 같은 장면의 대사만 바꾼 원고는 반려.
- 같은 개념의 후속 편은 이전 편과 새로 배우는 점의 차이를 명시.
- 10개 추천 주제 중 최소 5개 편집 축을 포함하고 한 축은 최대 3개.
- 댓글 단어·인물 포즈·마무리 문장이 연속 반복되지 않는지 별도 확인.
- 단어 겹침만으로 유익한 후속 설명을 막지는 않는다.

이 숫자는 운영 시작 기준이며 조회수 보장 공식이 아니다. 실제 저장·공유·완독을 대체할 수 있는 관측치·상담 문의를 보며 조정한다.

## 7. 분위기·캐릭터·글자 기준

현재 승인된 시각 기준을 유지한다. 이번 내용 강화는 새 그림체 요청이 아니다.

- 연지: 성인 한국 여성, 어깨 길이 짙은 머리, 크림 블라우스, 차분한 자두색 카디건.
- 타래: 작은 붉은 실 정령. 관계를 설명하는 보조 역할.
- 기준 이미지와 기존 캐릭터 설정을 매 생성에 참조. 얼굴·연령·머리·의상 임의 변경 금지.
- 따뜻하고 차분한 종이·과슈·색연필 웹툰 분위기. 과한 금박·신비광·부적 장식 추가 금지.
- 휴대폰·소파·슬픈 얼굴만 반복하지 않고 서로 다른 행동·거리·시점으로 장면 설계.
- 설명 장에서는 표정 대신 작은 도식·두 가지 글자 관계 비교를 사용할 수 있음.
- 한자·명식·본문은 이미지 모델에게 그리게 하지 않고 검수된 텍스트로 조판.
- 현재 앱의 글꼴·크기·색상 토큰을 유지. 새 폰트를 임의로 도입하지 않음.
- 제목 2~3줄, 본문은 대략 60~95자 안에서 의미 우선. 설명이 길면 문장을 줄이지 않고 장 배치를 재설계.
- 작은 면책문으로 중요한 제한을 숨기지 않음. 휴대폰 크기에서 직접 읽어 확인.
- 오탈자 검사는 원고뿐 아니라 최종 렌더링 이미지에서도 수행.

## 8. 캡션·해시태그·상담 연결

캡션은 ①이번 고민 ②그림에서 짧게 다룬 조건 보충 ③개인 풀이에서 볼 점 ④참여 또는 상담 안내 순서.
매번 같은 서문·마무리를 붙이지 않는다. 본문의 사주 설명과 캡션이 서로 모순되면 반려한다.

해시태그는 브랜드 공통 태그와 실제 주제 태그를 조합한다.
초기 편집 기준은 3~5개 정도이며 플랫폼 성과를 보장하는 개수는 아니다.
이혼 주제에 무관한 재회·도화 태그를 무작위로 붙이지 않는다.
자동게시·작업ID·계정 내부키·테스트 문자열은 이미지·캡션·댓글 어디에도 노출하지 않는다.

CTA 예:
- “댓글에 ‘부부궁합’이라고 남겨줘. 가장 알고 싶은 건 대화·거리감·결혼 중 어떤 부분이야?”
- “댓글에 ‘재회’라고 남겨줘. 다시 만나는 것보다 먼저 풀고 싶은 고민이 있다면 한 줄만.”
- “댓글에 ‘도화’라고 남겨줘. 매력과 오래 가는 인연의 차이, 다음 편에서 이어서 볼게.” — 실제 후속 기획이 있을 때만.

번호만 남기기, 복을 받으려면 댓글 달기, 특정 날짜 연락 보장 금지.
자동 DM이 구현되지 않았으면 “바로 보내줄게” 금지.
생년월일시·상대 정보는 공개 댓글로 받지 않는다. 개인 풀이 신청 시 동의받은 비공개 절차로 안내한다.
사주만으로 상대의 속마음이나 이혼 여부를 확정할 수 있다고 약속하지 않는다.

## 9. 새 원고 생성용 마스터 프롬프트

아래는 실제 생성 경로에 별도 연결해야 하는 프롬프트 초안이다.

역할:
너는 연리지 실타래의 사주 웹툰 편집자다. 관계 공감에 머무르지 않고 전통 명리의 개념·조건·적용 차이를 설명한다.
독자는 20~40대 여성이다. 친근한 반말을 쓰되 유아화·성별 고정관념·운명 단정을 피한다.

입력:
- topicBrief: 중심 질문, 편집 축, 독자가 새로 배울 점
- factPack: 정의, 적용 기준, 성립 조건, 출처, 해석 범위, 검토 상태
- recentHistory: 최근 원고·주제·핵심 원리·장면·결론·CTA
- lockedVisualBible: 승인된 연지·타래 기준, 분위기, 조판 기준
- availableActions: 실제 제공 가능한 상담·댓글 응답·자료·예약 기능

작성:
1. factPack의 핵심 근거가 없거나 검토 미완료면 blocked 상태로 부족한 근거만 반환한다.
2. 같은 질문·원리·결론의 기존 글이 있으면 차별점을 제안하거나 주제를 교체한다.
3. 7장 원고를 작성한다. 3~5장에는 명리의 정의·조건·적용 차이를 각각 구체적으로 배치한다.
4. 원고에서 사주 단어를 삭제해도 내용이 그대로인 일반 관계 조언이면 다시 작성한다.
5. 신살 이름을 행동에서 역추론하지 않는다. 전통 규칙·해석·창작 사례를 분리한다.
6. 매 장의 문장과 시각 장면은 서로 다른 역할을 한다. 기준 캐릭터는 바꾸지 않는다.
7. 마지막은 주제 관련 의미 있는 댓글 질문이다. availableActions에 없는 보상·자동 답장을 약속하지 않는다.
8. 캡션은 조건을 보충하고 실제 주제 해시태그를 선택한다.
9. 오타·논리·중복·단정·내부 식별자·읽기 크기 위험을 자체 점검한다.
10. 게시 승인을 대신하지 않는다. 결과는 review_required다.

출력 항목:
status, topicBrief, factPackReferences, noveltyComparedWithHistory,
cards[{number, role, title, body, sceneBrief, claimType, sourceRef}],
caption, hashtags, commentCTA, factChecks, unresolvedIssues, reviewRequired.

## 10. 제작·검수·승인 흐름

10개 주제 제안 → 사용자가 선택 → 근거 확인 및 7장 원고 → 원고 검수 → 이미지 제작 → 최종 이미지·캡션 확인 → 사용자 승인 → 지정 날짜 예약.

주제 카드에는 제목만 아니라 핵심 사주 개념·한 줄 학습 결과·기존 편과의 차이를 보여준다.
이미지 생성 전에 원고를 고칠 수 있어야 하며, 그림 재생성과 원고 수정을 서로 다른 동작으로 구분한다.

검수 게이트:
- 근거: 모든 판별 조건에 적용 기준과 자료가 있는가?
- 내용: 정의만 있고 조건·적용이 빠지지 않았는가?
- 정확성: 자리·띠·일주를 혼동하지 않았는가? 과장된 예측은 없는가?
- 흐름: 1장의 질문을 6장까지 실제로 설명했는가?
- 문장: 오타·조사·한자·띄어쓰기·캡션 일치 검사.
- 중복: 주제뿐 아니라 결론·대사·그림 구도가 겹치지 않는가?
- 시각: 여자 캐릭터 동일성, 글자 잘림·손·소품 오류, 모바일 가독성.
- 공개 정보: 내부 해시태그·작업 메모·키·임시 문구가 없는가?
- 승인: 승인된 이미지·문구와 예약 대상이 정확히 같은 버전인가?
- 중복 게시: 동일 원고 버전에 예약이 이미 있는지 확인하는 기존 안전장치 유지.

자동 검사 합격을 사람의 최종 승인으로 표시하지 않는다.
수정이 생기면 새 버전 재검수·재승인이 원칙이다. 이번 지침 작성에서는 기존 승인이나 예약 상태를 일괄 바꾸지 않는다.

## 11. 적용 범위와 다음 구현 작업

이번 반영: 이 지침과 동일 주제 7장 개선 원고를 문서로 작성.
아직 미반영: 기존 26개 템플릿의 재작성, 생성기 입력 연결, 내용 충실도 검사, 새 UI의 근거 표시.
따라서 앱에서 바로 재생성하면 새 지침대로 나온다고 안내하면 안 된다.

다음 구현은 연리지 신규 초안 생성 경로에만 제한한다.

이미 생성된 시안을 자동 재생성하거나 게시하지 않는다.
